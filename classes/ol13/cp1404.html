CP1404 · Programming II — giáo trình chuẩn bị

Phát triển chương trình Python có nhiều thành phần. Nền cần có từ CP1401 là hàm, vòng lặp và danh sách; phần mới là quản lý đối tượng, sự kiện giao diện (Kivy), quản lý phiên bản code (Git), test và debug, và một phần API/Flask.

Giả định khi lập kế hoạch
  • Giáo trình chuẩn bị trước khi vào JCU TR1S 2027, xây từ bản tóm tắt chủ đề theo tài liệu công khai của JCU. Đây không phải đề cương chính thức của môn; khi có handbook hoặc danh mục practical của kỳ học thì đối chiếu và điều chỉnh.
  • Mỗi buổi khoảng 90 phút. Chưa có lịch nên chưa gán ngày; số buổi chia theo nội dung, giáo viên gộp hoặc tách bài theo tiến độ thật.
  • Chưa biết chắc trình độ Python hiện tại của học viên, nên bài 01 có kiểm tra đầu vào. Nếu học viên vững thì rút bài 01 còn nửa buổi.
  • Công cụ: Python 3 bản mới, một IDE có debugger (PyCharm hoặc VS Code), Git, tài khoản GitHub, thư viện kivy, requests, flask cài bằng pip.
  • Đây là bản đề xuất. Giáo viên quyết định nội dung, thời lượng và mốc đánh giá chính thức.

3. Lộ trình từng bài

Bài 01 — Ôn nền CP1401: luồng điều khiển và hàm

Mục tiêu

  • Viết chương trình có main() gọi các hàm nhỏ, mỗi hàm một việc.
  • Phân biệt print trong hàm với return kết quả cho nơi gọi.

Nội dung

  • Cài Python, IDE, chạy file .py. Quy ước đặt tên snake_case, hằng số viết hoa.
  • if/elif/else, while (lặp đến khi nhập hợp lệ), for với range và list.
  • Hàm: tham số, giá trị mặc định, return nhiều giá trị, phạm vi biến (biến cục bộ, tránh biến toàn cục).
  • Mẫu chương trình: def main(): ... và gọi main() ở cuối file.

Thực hành trên lớp

  • Kiểm tra đầu vào 30 phút.
  • Tách một chương trình viết liền một khối (cho sẵn) thành 3–4 hàm, chạy lại để chắc kết quả không đổi.

Bài về nhà

  • 3 chương trình menu (nhập lựa chọn, lặp đến khi chọn Quit), mỗi lựa chọn là một hàm có return.

Keywords: control flow, function, parameter, return, main

Bài 02 — File và ngoại lệ

Mục tiêu

  • Đọc và ghi file văn bản/CSV bằng with open.
  • Đặt try/except đúng ở bước có thể thất bại, không bọc cả chương trình.

Nội dung

  • with open(filename, "r", encoding="utf-8") as in_file: file tự đóng khi ra khỏi khối (context manager). Chế độ "r", "w", "a".
  • Đọc từng dòng, strip(), split(","); module csv cho dữ liệu có dấu phẩy trong ô.
  • ValueError khi int()/float() gặp chuỗi sai, FileNotFoundError khi thiếu file. else và finally.
  • Vòng lặp kiểm tra input: lặp đến khi người dùng nhập số hợp lệ trong khoảng cho phép.

Thực hành trên lớp

  • Đọc file điểm (tên, điểm), bỏ qua và báo dòng lỗi, tính trung bình, ghi kết quả ra file mới.
  • Chạy thử với 3 trường hợp: file đúng, file có dòng sai kiểu, file không tồn tại.

Bài về nhà

  • Hàm get_valid_number(prompt, low, high) dùng lại được, và một chương trình đọc/ghi CSV dùng hàm đó.

Keywords: file I/O, context manager, try/except, ValueError, FileNotFoundError, csv

Bài 03 — List và dictionary

Mục tiêu

  • Chọn đúng cấu trúc dữ liệu dựa trên thao tác hay dùng: duyệt theo thứ tự hay tra theo khóa.

Nội dung

  • List: thêm, xoá, cắt, sắp xếp; sorted(items, key=...); list lồng (list of lists).
  • Dictionary: thêm/sửa theo khóa, get với giá trị mặc định, duyệt items(), đếm tần suất.
  • Khi nào dùng cái nào: tìm theo tên trong list phải duyệt hết, trong dict tra thẳng theo khóa.
  • List/dict comprehension cho các biến đổi đơn giản.

Thực hành trên lớp

  • Đếm số lần xuất hiện của từng từ trong một file, in theo thứ tự giảm dần.
  • Cùng một bài tra cứu viết bằng list và bằng dict, so sánh độ dài code và cách tra.

Bài về nhà

  • Chương trình quản lý danh bạ nhỏ (dict tên → số điện thoại giả lập), đọc/ghi file ở bài 02.

Keywords: list, dictionary, key, value, iteration, comprehension

Bài 04 — Lớp và đối tượng

Mục tiêu

  • Viết class có __init__, attribute, method và __str__.
  • Hiểu mỗi object giữ trạng thái riêng; method đọc/sửa trạng thái qua self.

Nội dung

  • Class là bản thiết kế, object là thể hiện. Tạo nhiều object từ một class, sửa một object không ảnh hưởng object khác.
  • Method trả giá trị và method thay đổi trạng thái. __str__ và __repr__ để in object.
  • Mỗi class một file module, import vào chương trình chính; file client riêng để thử class.
  • List các object: đọc mỗi dòng file thành một object, lưu vào list, sắp xếp theo attribute.

Thực hành trên lớp

  • Class Book (tên, tác giả, số trang, đã đọc hay chưa), method đánh dấu đã đọc, kiểm tra sách dài.
  • Đọc file sách thành list Book, in danh sách chưa đọc sắp theo số trang.

Bài về nhà

  • Tự chọn một đối tượng đời thường, viết class có ít nhất 3 attribute, 2 method và file client thử từng method.

Keywords: class, object, attribute, method, self, __init__, __str__

Bài 05 — Thiết kế class cho bài toán: Risky Business

Mục tiêu

  • Gom dữ liệu thuộc về nhau vào một object thay vì nhiều biến/list rời, rồi viết báo cáo trên list các object.

Nội dung

  • Theo bài tự kiểm tra trong bản tóm tắt: gom kết quả và trạng thái thắng/thua của mỗi lượt vào một object Turn.
  • Lưu các lượt trong một list; báo cáo tính trên list (tổng, số lượt thắng/thua, lượt tốt nhất).
  • Trường hợp biên: list rỗng không được làm chương trình chia cho 0 hoặc crash.
  • Luật chơi chi tiết lấy theo đề practical khi có; trên lớp dùng phiên bản đơn giản do giáo viên mô tả.

Thực hành trên lớp

  • Viết class Turn và hàm báo cáo. Kiểm tra báo cáo với đúng 3 trường hợp: một lượt lời, một lượt lỗ, danh sách rỗng.
  • So sánh với phiên bản dùng nhiều list song song: phiên bản nào dễ sửa khi thêm một thông tin mới cho mỗi lượt.

Bài về nhà

  • Thêm một attribute mới vào Turn và cập nhật báo cáo; ghi lại những chỗ phải sửa.

Keywords: class design, object, list of objects, edge case, empty list

Bài 06 — Kế thừa

Mục tiêu

  • Viết lớp con dùng lại lớp cha, override method khi lớp con cần xử lý khác.

Nội dung

  • class Child(Parent), gọi super().__init__(...) rồi thêm attribute riêng.
  • Override method; trong method override vẫn có thể gọi super().method() để dùng lại phần chung.
  • Lời gọi cùng một method trên list chứa cả object lớp cha và lớp con: mỗi object chạy phiên bản của mình.
  • Khi nào nên kế thừa (quan hệ "là một") và khi nào không nên.

Thực hành trên lớp

  • Class Vehicle có quãng đường và chi phí; lớp con Taxi tính giá theo km, lớp con của Taxi có phụ phí riêng. Override method tính giá và __str__.

Bài về nhà

  • Mở rộng class ở bài 04 bằng một lớp con có ít nhất 1 method override, kèm file client.

Keywords: inheritance, subclass, superclass, override, super()

Bài 07 — Testing và debugging

Mục tiêu

  • Viết test cho hàm và method, gồm cả trường hợp biên.
  • Dùng debugger để truy lỗi thay vì đoán hoặc rải print.

Nội dung

  • assert với thông báo lỗi rõ ràng; doctest viết ví dụ trong docstring.
  • Chọn test case: trường hợp thường, biên (0, rỗng, giá trị lớn nhất), dữ liệu sai.
  • Debugger trong IDE: breakpoint, step over, step into, xem biến (watch), xem call stack.
  • Đọc traceback: dòng cuối là loại lỗi, các dòng trên chỉ đường đi tới lỗi.

Thực hành trên lớp

  • Viết test cho class Turn (bài 05) và Taxi (bài 06).
  • Chương trình cho sẵn có 3 lỗi logic: dùng debugger tìm và sửa, ghi lại từng bước.

Bài về nhà

  • Bổ sung doctest cho các hàm ở bài 02 và 03, chạy cho tới khi tất cả pass.

Keywords: testing, assert, doctest, debugging, breakpoint, traceback

Bài 08 — Git, GitHub và code review

Mục tiêu

  • Quản lý code bằng Git: mỗi commit một thay đổi rõ ràng, làm việc qua branch và pull request.

Nội dung

  • git init, status, add, commit, log; viết commit message mô tả việc đã làm.
  • .gitignore cho file không cần lưu (__pycache__, file cấu hình máy cá nhân). Không bao giờ commit mật khẩu hay API key.
  • Remote trên GitHub: push, pull. Branch, mở pull request, review và sửa theo nhận xét.
  • Đọc git diff trước khi commit để chắc chỉ commit đúng thứ cần.

Thực hành trên lớp

  • Đưa code bài 01–07 lên một repo, mỗi bài ít nhất 1 commit.
  • Tạo branch sửa một lỗi, mở pull request, giáo viên review, học viên sửa và merge.
  • Nếu còn thời gian: kiểm tra giữa môn 60 phút (xem mục 2).

Bài về nhà

  • Review pull request của giáo viên (cố ý có lỗi), viết ít nhất 3 nhận xét cụ thể.

Keywords: Git, commit, branch, pull request, code review, .gitignore

Bài 09 — GUI với Kivy (1): bố cục và sự kiện

Mục tiêu

  • Dựng màn hình có ô nhập, nút, nhãn bằng file .kv; khi nhấn nút gọi một method trong Python.

Nội dung

  • Cấu trúc app: class kế thừa App, method build(), nạp file .kv.
  • Layout (BoxLayout, GridLayout), widget Label, Button, TextInput, đặt id để tham chiếu.
  • Sự kiện on_release gọi method của app; đọc TextInput.text, ghi Label.text.
  • Tách giao diện (.kv) khỏi xử lý (Python).

Thực hành trên lớp

  • App đổi đơn vị (ví dụ km sang dặm): nhập số, nhấn nút, hiện kết quả.

Bài về nhà

  • App nhỏ tự chọn với ít nhất 2 ô nhập và 2 nút.

Keywords: GUI, Kivy, .kv, layout, TextInput, Button, Label, on_release, event

Bài 10 — GUI với Kivy (2): xử lý input và kết hợp class

Mục tiêu

  • App không crash khi người dùng nhập sai; dữ liệu của app lấy từ các class đã viết.

Nội dung

  • Bắt ValueError trong method xử lý nút, hiện thông báo lỗi trên nhãn.
  • Tạo widget động từ list object (ví dụ mỗi object một Button), xoá/thêm widget.
  • App giữ trạng thái (list object) trong attribute; sự kiện cập nhật trạng thái rồi cập nhật giao diện.

Thực hành trên lớp

  • App danh sách sách dùng class Book (bài 04): đọc file, hiện mỗi sách một nút, nhấn để đánh dấu đã đọc, nhãn tổng số trang còn lại.

Bài về nhà

  • Bắt đầu mini project cuối môn: chọn đề, vẽ phác giao diện, liệt kê class cần có, tạo repo.

Keywords: input validation, dynamic widgets, app state, Kivy

Bài 11 — API và Flask

Mục tiêu

  • Gửi request tới một API công khai, kiểm tra response và xử lý dữ liệu JSON trả về.
  • Viết một web app Flask nhỏ có route trả HTML và JSON.

Nội dung

  • Mô hình request/response, HTTP method (GET, POST), status code (200, 404, 500).
  • requests.get(url, timeout=...), kiểm tra status_code, response.json() ra dict/list. Bắt lỗi mạng và lỗi dữ liệu thiếu khóa.
  • API cần key: đọc key từ biến môi trường, không ghi vào code, không commit lên Git.
  • Flask: @app.route, tham số trên URL, request.args, trả JSON, template đơn giản. Kiểm tra dữ liệu người dùng gửi lên trước khi dùng.

Thực hành trên lớp

  • Chọn một API công khai không cần key (giáo viên chuẩn bị), lấy dữ liệu, in ra 5 dòng đầu dạng bảng.
  • Flask app có route / và route trả JSON từ list object.

Bài về nhà

  • Thêm một route Flask nhận tham số, kiểm tra tham số hợp lệ, trả lỗi 400 khi sai.

Keywords: API, request, response, JSON, status code, Flask, route

Bài 12 — Ôn tập và mini project cuối môn

Mục tiêu

  • Hoàn thành mini project dùng đủ: file, class, kế thừa (nếu hợp), Kivy, test, Git.

Hoạt động

  • Nửa đầu: ôn các lỗi lặp lại từ bài kiểm tra giữa môn và bài về nhà.
  • Nửa sau: học viên demo app, giải thích thiết kế class, chạy test, trình bày lịch sử commit.
  • Giáo viên review code như một pull request, ghi nhận xét theo nhóm: cấu trúc, xử lý lỗi, test, Git.

Keywords: project, code review, refactoring
