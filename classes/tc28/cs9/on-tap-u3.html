A. Thuật ngữ, quy tắc, giá trịA. Terms, rules and values State · Define · Name · Give

Nhận diệnHow to spot it

  • Đề bắt đầu bằng State, Define, Name, Give, State the value. Thường 2–3 điểm, mỗi ý đúng 1 điểm.
  • The question starts with State, Define, Name, Give, State the value. Usually 2–3 marks, 1 mark per correct point.

Cách làmHow to answer

  1. Nhìn số điểm để biết cần bao nhiêu ý.
  2. Dùng đúng thuật ngữ trong sách: analysis → design → coding → testing; terminator, parallelogram, diamond.
  3. Define: nêu định nghĩa đầy đủ. Nếu đề hỏi thêm ví dụ thì cho ví dụ cụ thể.
  4. Câu tính giá trị: viết cả phép tính, ví dụ 23 DIV 6 = 3, 23 MOD 6 = 5.
  1. Use the marks to decide how many points to give.
  2. Use the exact textbook terms: analysis → design → coding → testing; terminator, parallelogram, diamond.
  3. Define: give the full definition. If an example is asked for, make it specific.
  4. Value questions: show the working, e.g. 23 DIV 6 = 3, 23 MOD 6 = 5.

Lỗi hay gặpCommon mistakes

  • Vòng đời phát triển chương trình thiếu bước hoặc sai thứ tự.
  • Abstraction chỉ ghi "làm đơn giản" mà thiếu vế "giữ lại chi tiết cần cho bài toán".
  • Nhầm DIV (phần nguyên) với MOD (phần dư).
  • SUBSTRING(s, start, length): vị trí đếm từ 1, ví dụ SUBSTRING("Cambridge", 4, 3) = "bri".
  • Chọn vòng lặp: biết trước số lần thì FOR; chạy ít nhất một lần thì REPEAT … UNTIL; có thể không chạy lần nào thì WHILE.
  • Missing a stage of the program development life cycle, or giving the stages in the wrong order.
  • Defining abstraction as just "making it simpler" without "keeping the details needed to solve the problem".
  • Mixing up DIV (whole-number part) and MOD (remainder).
  • SUBSTRING(s, start, length) counts from 1, e.g. SUBSTRING("Cambridge", 4, 3) = "bri".
  • Choosing a loop: known number of repeats → FOR; must run at least once → REPEAT … UNTIL; may not run at all → WHILE.

B. Giải thíchB. Explain Explain · Explain two reasons/benefits

Nhận diệnHow to spot it

  • Đề có Explain, Explain why, Explain two …. Thường 2–4 điểm.
  • The question says Explain, Explain why, Explain two …. Usually 2–4 marks.

Cách làmHow to answer

  1. Mỗi điểm là một ý. Đề "Explain two …" [4] thì mỗi lý do 2 ý: ý chính + hệ quả (viết theo mẫu "…, nên …").
  2. Gắn câu trả lời vào tình huống trong đề (nhóm 5 lập trình viên, chương trình nhập điểm 0–100…).
  3. Hai lý do phải khác nhau thật, không viết lại một ý bằng từ khác.
  1. One mark per point. For "Explain two …" [4], give each reason two points: the point + its consequence ("…, so …").
  2. Link your answer to the scenario in the question (a team of five programmers, a mark-entry program for 0–100…).
  3. The two reasons must really be different, not the same idea in other words.

Lỗi hay gặpCommon mistakes

  • Lẫn verification với validation. Verification kiểm tra dữ liệu nhập có khớp bản gốc không: visual check, double entry check. Validation kiểm tra dữ liệu có hợp lý không: range, length, type, presence, format, check digit.
  • Quên rằng validation không bắt được dữ liệu hợp lý nhưng sai, ví dụ nhập 15 thay vì 51.
  • Chỉ nêu ý chính mà không có hệ quả, nên mất nửa số điểm.
  • Mixing up verification and validation. Verification checks that the data entered matches the original: visual check, double entry check. Validation checks that the data is reasonable: range, length, type, presence, format, check digit.
  • Forgetting that validation cannot catch data that is reasonable but wrong, e.g. 15 typed instead of 51.
  • Giving the point without its consequence, which loses half the marks.

C. Phân rã, IPO, sơ đồ cấu trúc, lưu đồC. Decomposition, IPO, structure diagrams, flowcharts Give an example of each part · Describe the diagram

Nhận diệnHow to spot it

  • Đề cho một hệ thống và hỏi ví dụ Input / Process / Output / Storage, hoặc yêu cầu describe sơ đồ cấu trúc hay lưu đồ. Thường 4–5 điểm.
  • The question describes a system and asks for examples of Input / Process / Output / Storage, or asks you to describe a structure diagram or flowchart. Usually 4–5 marks.

Cách làmHow to answer

  1. IPO + Storage: lấy ví dụ từ chính đề. Input là dữ liệu đưa vào, Process là việc tính toán, Output là thứ hiện ra, Storage là thứ lưu lại (file).
  2. Sơ đồ cấu trúc: hộp trên cùng là cả hệ thống; tầng dưới là các hệ con; hộp con nối đúng dưới hộp cha bằng đường thẳng từ trên xuống.
  3. Mô tả lưu đồ: đi từ START đến STOP, nêu tên ký hiệu và nội dung từng hộp. INPUT/OUTPUT dùng parallelogram, xử lý dùng hình chữ nhật, quyết định dùng diamond có điều kiện chính xác và hai lối ra Yes/No, các hộp nối bằng flow line có mũi tên.
  1. IPO + Storage: take every example from the scenario. Input is the data going in, Process is the calculation, Output is what is shown, Storage is what is saved (a file).
  2. Structure diagram: the top box is the whole system; the next level holds the sub-systems; each lower box is joined under the correct parent box by lines going down.
  3. Describing a flowchart: go from START to STOP, naming each symbol and what it contains. INPUT/OUTPUT use a parallelogram, a process uses a rectangle, a decision uses a diamond with a precise condition and two exits labelled Yes/No, and all boxes are joined by flow lines with arrows.

Lỗi hay gặpCommon mistakes

  • Ví dụ chung chung, không lấy từ đề.
  • Đặt hộp con dưới nhầm hộp cha trong sơ đồ cấu trúc.
  • Dùng hình chữ nhật cho INPUT/OUTPUT, hoặc quên START/STOP.
  • Điều kiện mơ hồ ("đủ cao?") thay vì Height >= 1.2?.
  • Generic examples that are not taken from the scenario.
  • Putting a sub-system under the wrong parent box in a structure diagram.
  • Using a rectangle for INPUT/OUTPUT, or leaving out START/STOP.
  • A vague condition ("tall enough?") instead of Height >= 1.2?.

D. Bảng theo dõi (trace table)D. Trace tables Complete the trace table

Nhận diệnHow to spot it

  • Đề cho pseudocode hoặc lưu đồ, dữ liệu nhập theo thứ tự, và một bảng có sẵn tên cột. Thường 3–5 điểm.
  • The question gives pseudocode or a flowchart, the input values in order, and a table with column headings. Usually 3–5 marks.

Cách làmHow to answer

  1. Dòng đầu ghi giá trị khởi tạo (ví dụ Total = 0).
  2. Đi từng lệnh một. Chỉ ghi vào cột khi biến đó thay đổi; mỗi lượt lặp thường là một dòng mới.
  3. Kiểm tra điều kiện vòng lặp ở mỗi lượt: WHILE kiểm tra trước, REPEAT kiểm tra sau. FOR có STEP -2 thì đếm lùi.
  4. Lời nhắc (prompt) và OUTPUT ghi vào cột OUTPUT đúng thời điểm được in.
  5. Dùng dữ liệu nhập đúng thứ tự đề cho, gạch từng giá trị khi đã dùng.
  1. Put the starting values in the first row (e.g. Total = 0).
  2. Work through one statement at a time. Only write in a column when that variable changes; each pass of a loop is usually a new row.
  3. Check the loop condition on every pass: WHILE tests before, REPEAT tests after. A FOR loop with STEP -2 counts down.
  4. Write prompts and OUTPUT values in the OUTPUT column at the moment they are output.
  5. Use the input values in the order given, crossing each one off as you use it.

Lỗi hay gặpCommon mistakes

  • Chạy thừa hoặc thiếu một lượt vì đọc sai điều kiện dừng.
  • Quên cập nhật một biến thứ hai trong cùng lượt.
  • Ghi OUTPUT trong mỗi lượt trong khi lệnh OUTPUT nằm sau vòng lặp.
  • Tính sai MOD / DIV, nhất là với số chẵn/lẻ (Number MOD 2 = 0 là số chẵn).
  • One pass too many or too few because the stopping condition was misread.
  • Forgetting to update a second variable in the same pass.
  • Writing OUTPUT on every pass when the OUTPUT statement is after the loop.
  • Getting MOD / DIV wrong, especially for even/odd (Number MOD 2 = 0 means even).

E. Đọc thuật toán: output, mục đích, chỗ saiE. Reading an algorithm: output, purpose, fault State the output · State the purpose · Explain what has gone wrong

Nhận diệnHow to spot it

  • Đề cho một đoạn thuật toán ngắn, hỏi giá trị output, mục đích của thuật toán, vì sao kết quả sai, hoặc giá trị kiểm thử nào làm lộ lỗi.
  • The question gives a short algorithm and asks for the output, its purpose, why the result is wrong, or which test value would show up the error.

Cách làmHow to answer

  1. Chạy thử nhanh (dry-run) với dữ liệu đề cho, nháp một bảng theo dõi nhỏ.
  2. Mục đích: mô tả việc thuật toán làm bằng ý nghĩa (ví dụ "tính tổng các chữ số của một số"), không đọc lại từng lệnh.
  3. Chỗ sai: so output thực tế với output mong đợi, chỉ ra dòng gây lỗi, giải thích và viết cách sửa.
  1. Dry-run the algorithm with the given data using a quick trace table on scrap paper.
  2. Purpose: describe what the algorithm achieves (e.g. "adds up the digits of a number"), not each statement in turn.
  3. Fault: compare the actual output with the expected output, point to the line that causes it, explain why, and write the correction.

Lỗi hay gặpCommon mistakes

  • Đổi chỗ hai biến mà không dùng biến tạm: Temp ← NumA, NumA ← NumB, NumB ← Temp.
  • Khởi tạo Largest ← 0 sẽ sai khi mọi số đều âm. Nên gán giá trị đầu tiên nhập vào.
  • Lỗi > thay cho >= chỉ lộ ra ở đúng giá trị biên (ví dụ 50).
  • Swapping two variables without a temporary variable: Temp ← NumA, NumA ← NumB, NumB ← Temp.
  • Starting with Largest ← 0 fails when every number is negative. Use the first value input instead.
  • A > instead of >= error only shows up with the exact boundary value (e.g. 50).

F. Thuật toán chuẩn tính tayF. Standard algorithms by hand Bubble sort · Linear search · Check digit

Nhận diệnHow to spot it

  • Đề cho một danh sách hoặc một mã số, yêu cầu viết từng bước sắp xếp, tìm kiếm, hoặc tính check digit.
  • The question gives a list or a code and asks you to show each step of a sort, a search, or a check digit calculation.

Cách làmHow to answer

  • Bubble sort: so từng cặp kề nhau từ trái sang phải, đổi chỗ nếu sai thứ tự. Ghi danh sách sau mỗi lần so sánh nếu đề yêu cầu. Hết một lượt (pass) thì số lớn nhất đã về cuối. Đếm số lần đổi chỗ.
  • Linear search: so lần lượt từ phần tử đầu tiên, dừng khi tìm thấy. Số lần so sánh bằng vị trí tìm thấy; không có trong danh sách thì phải so hết n phần tử.
  • Check digit: làm đúng quy tắc đề cho (ví dụ cộng bốn chữ số rồi MOD 10), viết từng bước, rồi so với chữ số kiểm tra được nhập.
  • Bubble sort: compare each pair of neighbours from left to right and swap them if they are in the wrong order. Write the list after each comparison if asked. After one pass the largest value is at the end. Count the swaps.
  • Linear search: compare from the first item until the item is found. The number of comparisons equals the position found; if the item is not there, all n items are compared.
  • Check digit: follow the rule in the question exactly (e.g. add four digits, then MOD 10), show every step, then compare with the check digit that was entered.

Lỗi hay gặpCommon mistakes

  • Đổi chỗ cả khi cặp đã đúng thứ tự, hoặc bỏ sót cặp cuối của lượt.
  • Đếm sai số lần so sánh khi không tìm thấy.
  • Quên rằng check digit kiểu cộng không phát hiện được lỗi đổi chỗ hai chữ số (74191 và 47191 cho cùng tổng).
  • Swapping a pair that is already in order, or missing the last pair in a pass.
  • Miscounting comparisons when the item is not found.
  • Forgetting that an adding-up check digit cannot detect two swapped digits (74191 and 47191 give the same sum).

G. Kiểm tra hợp lệ và dữ liệu kiểm thửG. Validation checks and test data Name the check · Give test data

Nhận diệnHow to spot it

  • Đề mô tả một quy định (tuổi 5–18, mật khẩu ít nhất 8 ký tự…) và hỏi loại validation check phù hợp, hoặc yêu cầu cho ví dụ từng loại test data.
  • The question describes a rule (age 5–18, password at least 8 characters…) and asks for the most suitable validation check, or for an example of each type of test data.

Cách làmHow to answer

  • Validation check: range (trong khoảng), length (số ký tự), type (đúng kiểu, ví dụ số nguyên), presence (không bỏ trống), format (đúng khuôn, ví dụ DD/MM/YYYY), check digit (chữ số kiểm tra).
  • Test data (theo mark scheme của bộ bài):
    • Normal: hợp lệ, trong khoảng, phải được chấp nhận.
    • Abnormal: phải bị từ chối, do ngoài khoảng hoặc sai kiểu (ví dụ "ten").
    • Extreme: giá trị nhỏ nhất hoặc lớn nhất vẫn được chấp nhận (ví dụ 5 và 18).
    • Boundary: giá trị ở giới hạn cùng với giá trị ngay ngoài giới hạn (ví dụ 4 và 5, hoặc 18 và 19).
  • Luôn đưa giá trị cụ thể lấy từ khoảng trong đề, và nói rõ giá trị đó được chấp nhận hay bị từ chối.
  • Validation checks: range, length (number of characters), type (e.g. whole number), presence (not left empty), format (e.g. DD/MM/YYYY), check digit.
  • Test data (as used in these mark schemes):
    • Normal: valid data inside the range that should be accepted.
    • Abnormal: data that must be rejected, out of range or of the wrong type (e.g. "ten").
    • Extreme: the smallest or largest value that is still accepted (e.g. 5 and 18).
    • Boundary: a value on the limit together with the value just outside it (e.g. 4 and 5, or 18 and 19).
  • Always give specific values from the range in the question, and say whether each one is accepted or rejected.

Lỗi hay gặpCommon mistakes

  • Nhầm extreme với boundary.
  • Chọn type check khi quy định là về số ký tự (phải là length check).
  • Ghi "một số lớn" thay vì một giá trị cụ thể.
  • Mixing up extreme and boundary data.
  • Choosing a type check when the rule is about the number of characters (that is a length check).
  • Writing "a big number" instead of a specific value.

H. Viết pseudocodeH. Writing pseudocode Write pseudocode that …

Nhận diệnHow to spot it

  • Đề bắt đầu bằng Write pseudocode, thường kèm yêu cầu bắt buộc (dùng CONSTANT, dùng REPEAT … UNTIL, dùng LENGTH…). Thường 4–6 điểm.
  • The question starts Write pseudocode, often with required features (use a CONSTANT, use REPEAT … UNTIL, use LENGTH…). Usually 4–6 marks.

Cách làmHow to answer

  1. Gạch chân mọi yêu cầu trong đề. Mỗi yêu cầu thường ứng với 1 điểm.
  2. Viết theo khung: khai báo và khởi tạo → INPUT có lời nhắc → xử lý / vòng lặp → OUTPUT có thông báo.
  3. Dùng đúng cú pháp 0478: ←, CONSTANT VAT ← 0.2, FOR … TO … NEXT, REPEAT … UNTIL, WHILE … DO … ENDWHILE, IF … THEN … ELSE … ENDIF.
  4. Đặt tên biến có nghĩa (TotalMark, không phải t).
  5. Chạy thử lại với một giá trị hợp lệ và một giá trị sai trước khi chuyển câu.
  1. Underline every requirement in the question. Each one is usually worth 1 mark.
  2. Follow the frame: declare and initialise → INPUT with a prompt → process / loop → OUTPUT with a message.
  3. Use 0478 syntax: ←, CONSTANT VAT ← 0.2, FOR … TO … NEXT, REPEAT … UNTIL, WHILE … DO … ENDWHILE, IF … THEN … ELSE … ENDIF.
  4. Use meaningful identifiers (TotalMark, not t).
  5. Dry-run your answer with one valid and one invalid value before moving on.

Lỗi hay gặpCommon mistakes

  • Viết cú pháp Python (=, input(), thụt lề thay cho ENDIF).
  • Không dùng loại vòng lặp đề yêu cầu.
  • Quên khởi tạo biến tổng/đếm.
  • Điều kiện validation sai biên: "từ 6 đến 12 ký tự" là LENGTH(Name) >= 6 AND LENGTH(Name) <= 12.
  • Writing Python syntax (=, input(), indentation instead of ENDIF).
  • Not using the type of loop the question asks for.
  • Forgetting to initialise a total or a counter.
  • Getting a validation limit wrong: "between 6 and 12 characters" is LENGTH(Name) >= 6 AND LENGTH(Name) <= 12.

I. Sửa / bổ sung thuật toánI. Correcting and amending algorithms Identify the errors · Amend the algorithm

Nhận diệnHow to spot it

  • Đề cho thuật toán có lỗi (thường nói rõ số lỗi) hoặc yêu cầu thêm chức năng rồi viết lại toàn bộ. Thường 4–6 điểm.
  • The question gives an algorithm with errors (often saying how many) or asks you to add a feature and rewrite it in full. Usually 4–6 marks.

Cách làmHow to answer

  1. Đọc kỹ thuật toán phải làm gì, rồi chạy thử với vài giá trị để thấy chỗ sai.
  2. Mỗi lỗi: chỉ ra dòng, nói vì sao sai, viết dòng đã sửa. Thường 2 điểm một lỗi.
  3. Amend … write the complete amended pseudocode: viết lại toàn bộ, giữ nguyên phần đúng, biến mới phải có khởi tạo.
  4. Dò theo danh sách lỗi hay gặp bên dưới nếu chưa tìm đủ số lỗi.
  1. Read what the algorithm should do, then dry-run it with a few values to see where it goes wrong.
  2. For each error: identify the line, say why it is wrong, and write the corrected line. Usually 2 marks per error.
  3. Amend … write the complete amended pseudocode: rewrite all of it, keep the parts that are right, and initialise any new variable.
  4. If you have not found enough errors, work through the checklist below.

Danh sách lỗi hay gặpError checklist

  • Khởi tạo sai (Total ← 1 thay vì 0).
  • Toán tử so sánh sai (> thay vì >=, = thay vì <>).
  • Vòng lặp chạy sai số lần (FOR Count ← 1 TO 7 khi cần 8).
  • Quên tăng biến đếm.
  • Sai AND/OR trong điều kiện.
  • OUTPUT hoặc phép tính trung bình đặt sai chỗ (trong vòng lặp).
  • Có thể chia cho 0 khi chưa có dữ liệu: kiểm tra IF Count > 0 trước khi chia.
  • Wrong starting value (Total ← 1 instead of 0).
  • Wrong comparison operator (> instead of >=, = instead of <>).
  • Loop runs the wrong number of times (FOR Count ← 1 TO 7 when 8 are needed).
  • Counter not increased.
  • AND/OR the wrong way round in a condition.
  • OUTPUT or the average calculation in the wrong place (inside the loop).
  • Possible division by zero when no data was entered: check IF Count > 0 before dividing.
